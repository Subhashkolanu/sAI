# sAI Repository Audit

Audited: 2026-11-02

## Scope and method

- Reviewed the 31 tracked Python files, including all 29 files under `backend/` and `frontend/`.
- Excluded local virtual environments, bytecode, captured images, and ignored runtime data from source review.
- Checked the import graph after repairs, compiled all application and test modules, imported all 27 application modules, and ran the available tests.
- Inspected the working tree before editing. `run.py`, `data/profile.json`, `Logo.png`, and `launch_sai.bat` were already user changes/untracked items and were not rewritten. The audit temporarily exercised profile storage, then restored the user's existing profile content.

## Requested documents

The requested `AGENTS.md`, `CODEX_TASK_001.md`, `docs/ARCHITECTURE.md`, and `docs/ROADMAP.md` were absent from this checkout. The `docs/` directory did not exist before this audit. `README.md` is effectively empty (2 bytes), so there is no usable installation or architecture documentation.

## Fixed findings

### Search page always failed

`frontend/search.py` described itself as conversation search but instantiated `backend.search.SearchEngine`, which only provides web-search methods. Its call to `self.engine.search(keyword)` therefore raised `AttributeError` for every non-empty query. The page now uses `backend.memory.Memory`, whose `search()` method returns the displayed conversation records.

### Terminal mode was not an assistant

`backend/main.py` accepted arbitrary text but only printed an "I received" echo. The launcher advertised this as the Terminal assistant mode. It now routes commands through `CommandManager` and non-command text through `Assistant.reply()`; `exit` remains local and does not invoke the model.

### Package imports depended on launcher path mutation

Ten backend modules and two frontend modules imported `config` (and `commands.py` imported `assistant`) as top-level modules. Direct package imports failed with `ModuleNotFoundError: No module named 'config'`; this also risked two separate config module instances under different launch paths. These imports now consistently use `backend.*`. Importing all 27 application modules succeeds.

### Profile path depended on the current working directory

`ProfileMemory` defaulted to the relative path `data/profile.json`, which can point outside the project when launched from a shortcut or another directory. Its default now uses the configured project `DATA_DIR`; explicit paths remain supported.

### Shell-based audio launch

`backend/speech.py` launched a generated filename through `os.system`. The filename is presently generated by `tempfile`, so exploitation was not demonstrated, but invoking a shell is unnecessary. Windows playback now uses `os.startfile`, avoiding shell parsing.

## Verified remaining findings

### High: missing basic project documentation and reproducible installation path

- Evidence: the four requested guidance/architecture/roadmap files are absent, and `README.md` is 2 bytes.
- Evidence: no lockfile, package metadata, test configuration, or CI workflow is tracked.
- Impact: a fresh user has no documented Python version, environment setup, Ollama installation/model command, API-key configuration, test command, or supported platform statement. Requirements use only lower bounds, so installs are not reproducible.
- Recommendation: add concise setup and architecture documentation, a supported Python-version policy, and a tested dependency-lock strategy. Do not infer an exact lockfile from the current local environment without product direction.

### Medium: server-side request forgery boundary if web fetch becomes exposed

- Evidence: `backend/search.py:48-58` accepts an arbitrary URL and passes it directly to `requests.get`.
- Current exposure: no FastAPI route or UI path exposes `fetch_page` to untrusted callers in this checkout.
- Impact: if this helper is exposed to chat, plugin, or API input, it can request loopback/private-network URLs.
- Recommendation: before exposing it, validate scheme and resolved address, block private/link-local/loopback ranges, bound response size, and disable redirects to unsafe destinations.

### Medium: destructive file helpers have no containment policy

- Evidence: `backend/file_manager.py:83-93` recursively deletes any supplied directory; `backend/utils.py:114-119` deletes any supplied file.
- Current exposure: no assistant command routes user text to these functions, so no live exploit path was found.
- Impact: a future command integration could delete arbitrary user paths.
- Recommendation: require explicit confirmation at the caller and enforce an allowlisted workspace/data root for any AI-initiated operation.

### Medium: SQLite access is not synchronized across UI/background connections

- Evidence: `backend/memory.py:21-25` enables cross-thread use without a lock. The chat response runs in a background thread (`frontend/chat.py:119-124`) while the Memory page uses a separate `Memory` connection (`frontend/memory.py:21`) and can clear/read the same database.
- Impact: concurrent write/read or clear activity can produce `database is locked` errors on SQLite.
- Recommendation: centralize database access behind a lock/queue and set a SQLite busy timeout; add a concurrent read/write regression test.

### Low: GUI startup eagerly initializes optional heavy vision dependencies

- Evidence: `frontend/app.py:83` constructs every page at startup; `frontend/vision.py:24` constructs `Vision`; `backend/vision.py:28` constructs `easyocr.Reader`.
- Impact: the GUI can start slowly or require OCR model availability even when the user only wants chat.
- Recommendation: lazy-create the Vision page when selected and surface an actionable dependency/model error. This was not changed because it requires a UI lifecycle decision.

### Low: temporary Edge TTS audio files are retained

- Evidence: `backend/speech.py` creates a `NamedTemporaryFile(delete=False)` and starts playback without later cleanup.
- Impact: repeated high-definition speech creates orphaned MP3 files.
- Recommendation: use a managed playback lifecycle that deletes the file after the player exits.

## Circular-import result

No circular Python import path was found in the repaired application graph. The prior defect was inconsistent top-level versus package-qualified imports, not a cycle. The complete 27-module import check passes.

## Test coverage gaps

There were no tracked tests before this audit. `tests/test_regressions.py` adds four dependency-free checks for memory search, profile persistence, terminal model routing, and terminal exit behavior. Important uncovered areas remain:

- GUI page behavior and thread/UI lifecycle;
- Ollama and OpenAI integration, including failure states;
- microphone, TTS, webcam, and OCR hardware integration;
- filesystem search and destructive file operations;
- concurrent SQLite access;
- web search/fetch network behavior and URL-safety controls.
